# Восстановление платежа PayAnyWay

PayAnyWay в этом проекте подтверждает оплату только подписанным callback на `/api/webhook/payanyway`. Merchant API для опроса статуса не используется. Возраст платежа сам по себе не является основанием для отмены `PENDING`.

## Сроки реакции

- Пользователь вернулся без оплаты: ссылка остаётся доступной в истории платежей, автоматической отмены по возрасту нет.
- Пользователь сообщает о списании, а платёж остаётся `PENDING` более 10 минут: начать проверку как платёжный инцидент.
- За 15 минут проверить локальный платёж, журнал событий и входящие callback. Если подтверждения нет, передать запрос провайдеру вместе с внутренним ID платежа.
- Пока результат неоднозначен, не просить пользователя платить повторно и не менять статус вручную.

## Потеря или закрытие страницы оплаты

1. Попросить пользователя открыть «Платежи» в кабинете.
2. Для `PENDING` нажать «Продолжить оплату» или «Вернуться к оплате».
3. Внутренняя ссылка `/api/payment/payanyway/redirect?payment=<id>` заново формирует подписанную форму PayAnyWay из локального платежа. Секрет и платёжные поля пользователю не показываются.
4. Если ссылка отсутствует, пользователь может создать новый платёж. Старый `PENDING` не считать отменённым или оплаченным без callback.

## Пользователь сообщает о списании

1. Найти операцию в «Админка → Платежи» по email или внутреннему ID.
2. Проверить, что provider равен `PAYANYWAY`, сумма и время совпадают с сообщением пользователя.
3. Проверить timeline платежа и логи `webhook.payanyway.*`:
   - `rejected`, `amount_mismatch`, `subscriber_mismatch`, `operation_mismatch` требуют проверки данных;
   - `payment_update_failed` означает, что корректный callback получен, но локальная запись не завершилась;
   - отсутствие callback не доказывает ни оплату, ни отмену.
4. Сверить внутренний ID, сумму и идентификатор операции в кабинете PayAnyWay или через поддержку провайдера. Не копировать секрет проверки целостности в тикет или чат.
5. Если провайдер позволяет повторить уведомление, направить его на штатный Pay URL `/api/webhook/payanyway`. Иначе запросить повторную доставку у поддержки провайдера. Только корректно подписанный callback переводит платёж в `SUCCEEDED`.
6. После callback проверить:
   - платёж `SUCCEEDED`;
   - заполнены `paidAt`, `externalPaymentId` и `subscriptionProvisionedAt`;
   - в timeline есть «Оплата подтверждена PayAnyWay».
7. Если деньги подтверждены, но доступ не выдан, открыть «Админка → Контроль подписок» и запустить повтор выдачи. Эта операция не подтверждает сам факт оплаты.

## Чего не делать

- Не переводить `PENDING` в `CANCELED` только из-за возраста.
- Не выставлять `SUCCEEDED` прямым SQL или ручным редактированием БД.
- Не использовать «Проверить» в админке как доказательство оплаты PayAnyWay: без Merchant API эта команда вернёт `PENDING`.
- Не создавать пользователю второй платёж, пока первое списание остаётся неподтверждённым.
- Не выдавать доступ вручную до подтверждения суммы и операции подписанным callback.

## Данные для эскалации

Передать провайдеру внутренний ID платежа, сумму, валюту, время, email плательщика и известный ID операции. В локальном обращении зафиксировать результат сверки, время запроса провайдеру и итог callback. Секреты, токены и полный callback в обращение не помещать.
