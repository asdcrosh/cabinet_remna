# Матрица проверки платёжных провайдеров

Дата: 18 сентября 2026.

Этот документ разделяет локальные автоматические проверки и обязательную проверку в тестовом или production-контуре. Локальные тесты используют моки API провайдеров и не подтверждают доступность их реальных систем.

## Локальная автоматическая матрица

| Сценарий | YooKassa | PayAnyWay | Platega |
| --- | --- | --- | --- |
| Успешная оплата и выдача | Проверено webhook и reconciliation | Проверено подписанным callback | Проверено callback и reconciliation |
| Отмена | Проверено по свежему статусу API | Нет отдельного callback отмены в текущей интеграции | Проверено callback |
| Pending | Проверено `pending` и `waiting_for_capture` | Источник истины только успешный подписанный callback | Проверено polling статуса |
| Повтор события | Выдача идемпотентна | Повтор операции не выдаёт доступ снова | Повтор запускает только безопасную довыдачу |
| Позднее событие или иной порядок | Webhook сверяется со свежим API | Успех привязывается к одному operation ID | Поздняя отмена не отменяет успешный платёж |
| Недоступность API или потерянный ответ | Ошибка проверки не считается оплатой; create защищён checkout key | Создание формы локальное; URL можно восстановить через защищённый redirect | Повтор create защищён checkout key, reconciliation доводит результат |
| Чужой payment ID | Проверяются внешний ID и metadata | Проверяются transaction ID, subscriber и закреплённый operation ID | Поиск только по provider + external ID |
| Неверная сумма или валюта | Проверяется точное совпадение суммы и RUB | Подпись и локальная сумма должны совпасть | Подтверждённая сумма не ниже заказа, валюта RUB; комиссия может быть сверху |
| Chargeback или refund | Полный и частичный refund | В текущей интеграции нет отдельного обработчика возврата | Общий обработчик chargeback для webhook и reconciliation |

## Обязательная проверка перед выпуском

- [ ] Создать по одному минимальному платежу у каждого реально включённого провайдера.
- [ ] Подтвердить success, cancel и длительный pending там, где провайдер поддерживает эти состояния.
- [ ] Повторить webhook и отправить события в изменённом порядке.
- [ ] Оборвать ответ после create и восстановить тот же checkout без второго списания.
- [ ] Проверить отказ callback с чужим ID, неверной суммой и валютой.
- [ ] Убедиться, что успешный платёж получает доступ один раз, а довыдача восстанавливается после сбоя.
- [ ] Сверить локальный финансовый журнал, кабинет провайдера и фактическое право доступа.
- [ ] Для PayAnyWay пройти процедуру из `docs/runbooks/payanyway-payment-recovery.md`.

Фиксировать для каждого запуска: среду, локальный payment ID, внешний ID, время события, итоговый статус, факт выдачи и ссылку на обезличенный лог. Секреты, платёжные ссылки и персональные данные в отчёт не копировать.
